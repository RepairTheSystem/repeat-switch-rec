# Одностадийная рекомендательная модель с режимом повторов

Одностадийные генеративные модели заменяют каскад «кандидаты → ранжирование» одной моделью. В музыке повтор —
главный позитивный сигнал, а на маркетплейсе режимов два: **расходники** (корм, вода) нужно повторять вовремя,
**товары длительного пользования** (холодильник) — не повторять вовсе.

**Гипотеза:** одностадийной модели на маркетплейсе нужен выученный переключатель «повтор / новое» на каждый запрос,
и он лучше фиксированной квоты повторов в выдаче.

Модель — SASRec-подобный трансформер + механизм RepeatNet (Ren et al., AAAI 2019): repeat-голова (pointer на историю
с учётом «возраста» каждой покупки), explore-голова (softmax по каталогу без истории) и переключатель
`P = p·P_repeat + (1−p)·P_explore`.

## Варианты

Правила смешивания (`mixing.py`) применяются к одним и тем же головам — эвристическим (`heur/…`) или нейросетевым
(`nn/…`), так что эффект правила изолирован.

| вариант | что делает |
|---|---|
| `freq+pop`, `tifu-knn` | сильные простые бейзлайны: история по частоте + популярное; упрощённый TIFU-KNN |
| `*/base` | одна шкала без режимов (`nn/base` — модель с одной головой) |
| `*/fixed-tuned` | квота q слотов из repeat-головы, q подобран на val |
| `*/switch` | мягкая смесь с выученным `p` на запрос |
| `*/route` | жёсткий роутинг: `p > thr` → вся выдача из repeat-головы, иначе из explore |
| `*/oracle-switch` | `p` = истинная доля повторов в целях — верхняя граница |
| `nn+mask/…` | explore-голова исключает **всю** историю, а не только окно последних 50 покупок |

## Методология

- **Синтетика с известной правдой**, три режима по доле повторов среди целей: `high` 0.82–0.88, `mid` 0.23–0.54,
  `low` 0.13–0.37. Шум: смена бренда, паузы-отпуска, сезонные категории.
- **Протокол:** обучение до дня 351, val-окно `[351, 358)` — ранняя остановка и подбор квоты, порога, гиперпараметров;
  test-окно `[358, 365)` — только отчёт. Запрос в начале окна, цели — все покупки окна.
- **Метрики:** Recall@10, NDCG@10, Recall отдельно по repeat- и explore-целям, `wasted slots` (повтор уже купленного
  товара длительного пользования), AUC/Brier переключателя.
- 3 сида × 3 режима, парный бутстрап по пользователям (95% CI).

## Результаты (Kaggle GPU, тест)

Recall@10, среднее ± std по сидам (сид меняет и данные, поэтому сравнивать варианты нужно парно внутри сида;
строка `nn+mask` — из отдельного прогона абляции на тех же данных):

| вариант | high | mid | low |
|---|---|---|---|
| `freq+pop` | 0.824 ± 0.023 | 0.351 ± 0.169 | 0.218 ± 0.133 |
| `heur/fixed-tuned` | 0.834 ± 0.022 | 0.515 ± 0.066 | 0.457 ± 0.040 |
| `nn/base` | 0.806 ± 0.016 | 0.433 ± 0.108 | 0.346 ± 0.078 |
| `nn/fixed-tuned` | 0.843 ± 0.016 | 0.543 ± 0.066 | 0.463 ± 0.050 |
| `nn/route` | 0.834 ± 0.023 | 0.466 ± 0.091 | 0.414 ± 0.058 |
| **`nn/switch`** | **0.853 ± 0.016** | **0.566 ± 0.064** | **0.492 ± 0.058** |
| **`nn+mask/switch`** | **0.851 ± 0.017** | **0.613 ± 0.043** | **0.547 ± 0.042** |
| `nn/oracle-switch` | 0.871 ± 0.008 | 0.593 ± 0.056 | 0.507 ± 0.057 |

**Выводы**

- **Гипотеза подтверждается на синтетике.** `nn/switch` лучше подобранной на val квоты во всех 9 прогонах
  (CI выше нуля): +0.006…+0.014 Recall@10 при 82–88% повторов и +0.019…+0.037 при 13–54%.
  До оракула остаётся 0.008–0.036.
- **Мягкая смесь лучше жёсткого роутинга** на 0.013–0.126: у многих запросов среди целей есть и повторы, и новое.
- **Простые правила сильны только при почти одних повторах:** `freq+pop` отстаёт на 0.03 в high и падает до 0.22–0.35
  в mid/low, потому что не рекомендует новое.
- **Лишние повторы — артефакт окна истории.** В mid/low `nn/switch` тратил ~2 слота из 10 на уже купленные холодильники;
  98% таких слотов — товары, выпавшие из окна последних 50 покупок, которые explore-голова не исключала. Маска полной
  истории (`nn+mask`) убирает их на 99.6% и даёт +0.03…+0.08 Recall@10 во всех 6 прогонах mid/low.
  Опции repeat-головы (обучаемая «повторяемость», пустой слот, счётчиковый приор) сверх маски ничего значимого не добавляют.
- **Утечка времени запроса** (старый протокол: запрос в момент покупки) на этой синтетике ничего не стоит: ±0.02 без знака.

**Латентность** (`latency_bench.py`, online = один запрос, от истории до топ-10):

| вариант | параметры | online p50, CPU ноутбука | online p50, GPU Kaggle | батч GPU, мс/польз. |
|---|---|---|---|---|
| `nn/base` | 203 456 | 1.48 мс | 2.66 мс | 0.061 |
| `nn/switch` | 209 729 | 2.27 мс | 3.93 мс | 0.112 |
| `nn+mask/switch` | 209 729 | 2.33 мс | 4.02 мс | 0.115 |

Маска почти бесплатна (+2%); переключатель стоит ×1.5 к online-задержке. При batch=1 GPU не быстрее CPU — время уходит
на Python-обвязку.

**Ограничения:** доля повторов внутри режима гуляет между сидами (число расходных категорий случайное); синтетика устроена
в духе модели; каталог 1500 товаров; ранняя остановка шумная (разброс прогон-к-прогону до 0.009 Recall).

## Запуск

```bash
pip install -r requirements.txt
python train.py --lr-base 1e-3 --lr-switch 3e-3                 # 3 режима × 3 сида
python train.py --regimes high --seeds 0 --out results/quick    # один прогон
python train.py --skip-nn                                       # только бейзлайны и эвристики
python train.py --switch-variants switch mask                   # без полной абляции
python latency_bench.py --device cpu
```

На GPU — `kaggle/repeat_switch_kaggle.ipynb`: самодостаточный ноутбук (снимок кода в ячейках `%%writefile`).
Kaggle: *File → Import Notebook*, *Accelerator → GPU*, *Save & Run All*; результаты — `results.zip` во вкладке *Output*.
Сырые результаты прогонов — в `results/`.
